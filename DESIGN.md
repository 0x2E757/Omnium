# Omnium — design record

Omnium is the single local marketplace housing its plugins as committed,
zero-dependency, human-readable source. This file is the binding decision record; the full
expert reports it condenses live in `docs/design/`. The migrated plugins
below carry a frozen-surface contract from their upstream releases; the
repo-native plugins (`cautium` D15, `sessio` D16, `statusline`, `distillum`
D18, `contextum` D20, `spatium` D22) have no such predecessor. The prime directives, in
priority order:

1. **No breaking changes.** Every user-visible surface of the migrated plugins
   (expertum 0.3.5, graphyne 0.1.28, memosyne 0.1.64) is frozen: tool names and
   input schemas, error-message text, hook events/outputs, command names,
   on-disk store formats, env vars. The exhaustive contract with per-surface
   verification is `docs/design/design-ai-engineer.md` §(a). Three sanctioned
   exceptions, all by user directive: D17 retires `memosyne_patch_task` — its
   name, input schema, and error text — for `memosyne_edit_task` (breaking bump
   to memosyne 0.4.0); D19 retires the **whole** autonomity plugin (last shipped
   0.4.5; its floor was 0.1.5), so its commands, hooks and state leave with it.
   D21 retires expertum's 54 per-expert **agent names** for a single
   `expertum:analyst` (breaking bump to expertum 0.9.0).
   Those are the only breaks; every other frozen surface stands.
2. **Zero runtime dependencies, no build.** `plugins/<name>/` is byte-for-byte
   what installs; an import that is not `node:*` or relative is a defect
   (guarded by tests).
3. **Human-readable code.** The 15-rule style charter in
   `docs/development.md` is binding.
4. **Cross-platform.** Every plugin must work on Windows, macOS, and Linux.
   Shipped code must not rely on POSIX-only mechanisms (uid/gid checks, file
   permission bits as the sole protection, `/tmp`, POSIX signals, `sh`-specific
   shell syntax, case-sensitive path assumptions); use `node:path`/`node:os`
   abstractions and platform-neutral designs. A solution that is correct only
   on Linux is a rejected solution.

| D15 | Fifth plugin `cautium`: an always-on, zero-config security-conscience injector — a single `SessionStart` hook emits a three-layer primer as `additionalContext`: (1) six universal security duties (secrets, injection-safe input, least-priv authN/Z, supply-chain, crypto/TLS, never-disable-a-control); (2) a universal 0-10 change-impact rubric (autonomous / confirm-per-step / explicit-approval tiers + PID-targeted process kills); (3) an **OS-dependent** risk mapping keyed on `process.platform` (Linux calls out `/etc`, systemd, firewall/exposure, `fstab`/GRUB, `rm -rf`, SSH severing, `pkill`/`killall`; Windows calls out the registry, `PATH`/environment, OS settings, scheduled tasks/services, elevation/UAC, `taskkill`; macOS calls out `launchd`/`launchctl`, SIP, Gatekeeper, Keychain, Homebrew, `sudo`, `killall`; generic OS-neutral fallback for the rest). The root is read from the **`CLAUDE_SESSIONS_DIR`** env var (a FROZEN surface per D1; user/OS-specific, never hardcoded); when unset the hook does NOT go quiet — it injects an ONBOARDING primer that has the agent ask the user for a base dir and persist the env (recommended: Claude Code settings `env` in `settings.json`, applied cross-platform to the session and its hooks). No MCP server, no commands, no state, no other events; dispatcher fails OPEN; no fs writes (the agent mkdirs on demand). Repo-native — outside D1's freeze except the new `CLAUDE_SESSIONS_DIR` knob; born at 0.1.0. Mirrors the cautium/autonomity zero-dep IO-shell/pure-lib split | user directive (this session) |
| D17 | Retire `memosyne_patch_task` + its vendored fuzz-0 jsdiff@9.0.0 `applyPatch` port (`plugins/memosyne/common/unified-diff.mjs`) and the differential oracle; replace with a single LLM-native `memosyne_edit_task` — an exact `old_text`/`new_text` targeted editor (Claude Code `Edit` model: read-first, literal byte-match, unique-or-fail unless `replace_all`, empty `new_text` deletes), reusing the retired handler's lock / stale-Done guard / per-section validation. | D18 | Eighth plugin `distillum`: a session-knowledge distiller — two markdown commands only, no hooks, no MCP server, no state, zero runtime code. `/distillum:to-skill` distills **procedural** knowledge (a procedure the session figured out) into a reusable skill, user-level or project-level, behind quality gates: an honesty gate (refuse an empty harvest), dedup against existing skills (update, never fork the trigger surface), a portability test for placement, trigger-phrase discipline for the frontmatter description, wrong turns embedded as warnings at the step where they bite, and a replay test against the session itself. `/distillum:to-docs` distills **declarative** knowledge (decisions + rationale, constraints, behavior that contradicted assumptions) into the project's existing documentation home — decision record / CLAUDE.md / docs / module headers — reconciling against what is written and fixing drift when the docs contradict the session; doc-sync obligations are honored via whatever tooling the session has active, phrased generically. When the harvest is the other kind (or mixed), each command distills its own kind and recommends the sibling to the user — it never invokes the sibling itself. **Standalone directive:** distillum must work as the ONLY installed Omnium plugin — its shipped surfaces (commands, README, plugin.json) name no sibling plugin and no sibling's tools, so it never sends a foreign agent hunting for tooling that isn't there; gate/sync integrations are written as generic capability descriptions that in-session tooling instructions (e.g. Graphyne's own hooks) bind to concrete tools. The boundary vs memosyne — memosyne remembers tasks (what we are doing), distillum extracts knowledge (what we learned) — is recorded here only, not in shipped files. Repo-native — outside D1's freeze; born at 0.1.0 | user directive (this session) |
| D19 | **Retire the `autonomity` plugin outright** (last shipped 0.4.5): `plugins/autonomity/`, `tests/autonomity/`, its marketplace entry, its `.plugin-versions.json` stamp, both README rosters, the SECURITY note and the state-map/troubleshooting rows are deleted. Rationale: Claude Code drives itself autonomously now (ultra code + `/loop`), so a per-session "autonomous mode" is a workaround for a gap that closed — and its guards were the weakest part of the fleet by design (an `AskUserQuestion` deny plus a blanket `allow` that bypasses the permission system wholesale, on top of best-effort `git push`/cwd/`CronDelete` denials that never claimed to be a sandbox). Permission modes and the harness's own gates do that job better and with real enforcement; the clean-git Stop gate is the one idea worth missing, and it is a hook anyone can re-add per repo. **Second sanctioned break of directive 1** after D17 — the retirement of a whole plugin rather than of one surface inside it; consumers run `/plugin uninstall autonomity@omnium`, and the only state, `${os.tmpdir()}/claude-autonomity/`, is disposable. Nothing depended on it: it shipped no MCP server and was deliberately absent from `scripts/sync-shared.mjs` CONSUMER_DIRS (D2/D13), so the only couplings were prose — the `shared/path-key.mjs` "lockstep with autonomity hook-lib" note (now dropped; the fold policy has no second copy to track) and the graphyne/memosyne hook comments that cited its erase-the-prompt toggle pattern (re-anchored to the pattern itself). D7/D15/D16 keep their autonomity references as **historical record**, as do the frozen expert reports in `docs/design/` — this row is the single superseding statement | user directive (this session) |
| D20 | Plugin `contextum`: context management around a task — two markdown commands only, no hooks, no MCP server, no state, zero runtime code. `/contextum:prepare <topic>` takes a short description of *what* the context is about, gathers it, and ends with a briefing; it edits nothing, does not start the task, and proposes no plan. Two binding choices: (1) **the main agent reads the material itself** — a delegated search returns only a conclusion to the main conversation, so the coming task would re-read everything; delegation is allowed for *locating* in a large codebase, never in place of reading the key files. This is what separates it from an Explore-style subagent (conclusion only) and from plan mode (a plan, not loaded context); (2) **the briefing is a human checkpoint, not a summary** — ~15–25 lines in the user's language: the interpretation chosen (ambiguity is resolved by picking and flagging, not by asking up front — the briefing is where the user corrects it), `file:line` anchors each marked ✓ read or ~ inferred, how it actually works, decisions & history, a **Not found / not examined** section that is never empty by default (a miss is easier to spot among what was skipped than as an absence among finds), and open questions. A user-invoked **command**, not a model-invocable skill: the value is the human checking the briefing, which an unprompted self-invocation would skip. Gathering spans central code, callers, tests, git history/blame, recorded decisions (decision record, CLAUDE.md, docs), open work, and edit gates/config. `/contextum:report [task]` audits the **current** context, read-only and without gathering more (gathering would change the thing audited). Scope: with a prompt, judged against that task; **without one, against the whole session** — not "no scope", because much of a context is filled independently of any task (CLAUDE.md/AGENTS.md, hook injections, agent/skill/tool rosters, MCP instructions), so dead weight is meaningful even unscoped. Two lists: (a) **dead weight**, each item sourced as `[environment]` (task-independent injections — recurring every session, fixed once in configuration, hence often the most valuable finding) / `[agent]` (its own irrelevant reads, oversized outputs, dead ends) / `[user]`, with a rough large/medium/small weight — never invented token counts; (b) **weak spots** under one rule — *if the agent cannot point to where in this session it read it, it is an assumption* — classed inferred / stale / compacted (known only via a compaction summary; stated, never passed off as the original) / from memory / second-hand / conflict / missing, ranked by how much the scope rests on each, each paired with the step that would firm it up. Evidence over self-assessment is the point: agents overrate what they know. The pair is complementary — `report` exposes gaps, a targeted `prepare` closes them. D18's **standalone directive** applies: shipped surfaces name no sibling plugin or tool — task memory, trackers and gates are described as generic capabilities. Repo-native — outside D1's freeze; born at 0.1.0 with both commands | user directive (this session) |
| D21 | **Expertum registers ONE sub-agent, `expertum:analyst`; its 54 expert lenses are data served over MCP.** Every registered sub-agent costs a roster line (name + description + tools) in the main agent's context in **every** session, used or not — the 54 analysts measured ~21.5k characters, ~5–7k tokens. Claude Code offers no way around it (verified against the docs: no hidden/visibility frontmatter field, no inline tools or system prompt on the Agent tool, no per-agent enable; a permission `deny` blocks the agent outright), so the lenses stop being agents. The 54 files were uniform — identical `tools:` line, no `model`/`effort`, byte-identical "Your brief"/"Output" sections and read-only paragraph — differing only in the role line, **Focus** and **Method**; those move to `plugins/expertum/experts/<name>.md` (front matter `name`/`group`/`domain` + body), the shared skeleton moves verbatim into `agents/analyst.md`, and the ownership boundaries into `experts/_lanes.md`. Two MCP tools on the existing server (`common/experts.mjs`): `expertum_overview` — the roster (name + one-line domain, grouped in a fixed order) plus the lanes; the five commands call it instead of carrying their own roster tables (single source of truth; those tables had already drifted from the README's) — and `expertum_expert(name)`, which the analyst calls **itself** as its first step (the main context stays lean; the alternative of the orchestrator pasting each lens into the brief was rejected) and on a missing/unknown name stops rather than analyzing generically — it writes no report and replies `NO REPORT: …`, and every command re-spawns such an analyst once and otherwise names the missing lens (in the conduct loops a missing review is never "satisfied"). The spawn protocol is owned by two constants in `experts.mjs` (`ANALYST_AGENT`, `EXPERT_BRIEF_LINE`) that the overview renders; its restatements in `analyst.md` and the commands are pinned to them by the parity test, which also checks that every expert named in shipped prose exists in the catalog. Names resolve through the loaded map only — never into a path. The catalog loads lazily once; a load failure is an in-band tool error that leaves `expertum_write_report` untouched. `expertum_write_report` keeps its frozen name/schema/text and its first place in `tools/list`. `tests/expertum/agent-parity.test.mjs` now pins exactly one agent file, the analyst's exact tool set, the four modes, and that every command spawns `expertum:analyst` via the overview and names no retired `expertum:<name>` type. **Third sanctioned break of directive 1** after D17 and D19: the 54 `expertum:<domain>--<lens>` agent names (the "Agent names" row of `docs/design/design-ai-engineer.md` §(a), kept there as historical record) are retired; breaking bump to expertum 0.9.0. Expert names, report filenames, modes and templates are unchanged | user directive (this session) |
| D22 | Plugin `spatium`: time awareness for the agent. Hooks inject the real time on `UserPromptSubmit` (full local date, UTC offset and weekday, since without an offset a model assumes UTC; also the gap since the last reply and the previous turn's total), after every `PostToolUse`/`PostToolUseFailure` (a one-line tick: clock + the current prompt's agent time), and a short primer on `SessionStart`. **Budgets** are user-set per prompt: `/spatium:budget <dur> <task>` is a *guide*, `/spatium:limit <dur> <task>` a *hard limit the agent enforces on itself*. Neither is ever enforced by the harness (a PreToolUse deny would stop an agent mid-edit, which is worse than an overrun); the tick then shows the share used, which may pass 100% (`112%, over by 3m30s`). Guidance is announced once per step (50 / 80 / 100, then every +50%); a hard limit past 100% repeats its stop order on every tick. Every declaration carries "never trade correctness for time silently", because budget pressure otherwise invites unreported corner-cutting. **The hook, not the agent, reads the budget**: `UserPromptSubmit` receives the raw typed slash command (the same fact graphyne's `/graphyne:off` interception rests on), so the markdown commands only brief the agent; they are `disable-model-invocation`, since a model-invoked command never passes through that hook. **Scope = one prompt**: every ordinary prompt clears the budget, so a stale budget can never leak into the next task; `/spatium:continue [+dur \| dur]` is the explicit carry-over (it keeps the clock, extends or resets the total, and charges none of the user's reply time). Agent time excludes waits on the user: `PreToolUse` (matcher `AskUserQuestion` only) opens a wait that `PostToolUse` closes. **User stamps outside the model context**: `UserPromptSubmit` and `Stop` also emit a `systemMessage` (shown to the user, never to the model, so zero tokens): the clock at the start of the turn (plus the budget) and the clock with the turn time or budget share at its end. No hook fires between the agent's messages inside a turn, so per-message stamps are impossible. `SPATIUM_USER_STAMPS=0` silences them, but a budgeted turn is always reported. `Stop` also records the turn for the next header. **Background-task notifications** arrive through `UserPromptSubmit` too, often mid-turn (observed live): a prompt starting with `<task-notification>` or `[SYSTEM NOTIFICATION` gets a tick only and never restarts the clock or clears the budget. Subagent ticks (payload `agent_id`) show the parent's budget but never record an announcement, so the main agent still gets it. **One file** (`hooks/spatium.mjs`) by user directive, because the hook runs on every tool call: the charter rule 2 split is kept *inside* the file (a pure, exported core above an "IO shell" banner that runs only when the file is the entry point, via `import.meta.main` with a path-compare fallback), and that is the sanctioned deviation from the cautium/sessio two-file shape. State: `${CLAUDE_PLUGIN_DATA}/sessions/<session_id>.json` (os tmpdir under `--plugin-dir`), where a session id that is not a plain token is refused as a path. Only turn boundaries, announcements and waits write it (temp + rename); ticks only read it, so parallel tool calls cannot race on anything that matters. Files idle for 7 days are pruned on `SessionStart`. Fails OPEN throughout. Cost: one `node` spawn and ~30-40 context tokens per tool call. Repo-native, outside D1's freeze; first released at 0.1.2 (0.1.0 and 0.1.1 were local-only iterations) | user directive (this session) |

## Verified mechanics the design rests on

- MCP tool prefix is `mcp__plugin_<plugin>_<server>__<tool>` — marketplace name
  never appears; the omnium switch changes no tool/command/agent name.
- Cache: `~/.claude/plugins/cache/<marketplace>/<plugin>/<version>/`; directory
  marketplaces are registered in place (catalog reads the live tree; installed
  plugins are copies refreshed only on version change).
- Hooks use exec form (`"command": "node"` + `args`; doc-recommended for path
  placeholders) — spawned directly, no shell on any platform. Shell form would
  run via `sh -c` (macOS/Linux) or Git Bash/PowerShell (Windows). No
  runtime-version enforcement; hooks fail OPEN — hence the `.mjs` floor decision.
